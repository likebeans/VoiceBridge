完成一次真实录音

本轮本地联调使用 FunASR，示例显式发送 provider: "funasr"。服务端需配置 SERVICE_API_KEY 及该供应商密钥；浏览器通过业务后端或网关连接，由代理注入请求头，浏览器不填写密钥。后续部署以能力接口返回为准。

  1. 在项目根目录运行下面的命令，启动后端。
  2. 让业务后端或网关转发 /v1/asr（含 WebSocket Upgrade）与 /v1/asr/capabilities，在转发时注入 X-API-Key，再通过代理打开 /demo。直接打开本服务试录页没有这个请求头时，会显示鉴权提示，不能录音。
  3. 选择已配置的 FunASR，语言默认自动识别，也可从菜单指定语言；点击开始并允许麦克风权限，等页面显示“正在录音”再说话。
  4. 说两句话，中间短暂停顿。点击停止后等待最后一句定稿及 done，再编辑或使用结果。
  5. 在开发者工具 Network → WS 中查看 /v1/asr 的消息，确认完整顺序。再测试取消、权限拒绝和录音中断网。
阅读页与录音页的使用位置不同

/guide 是服务内文档，/demo 是真实录音入口。发布在 Artifact 中的这份文档仅用于阅读和复制代码，不能访问麦克风，也不能连接你的 localhost WebSocket。

录音需要安全上下文。同一台电脑上的 http://localhost 或 http://127.0.0.1 通常可用；线上使用 HTTPS 与 WSS。手机上的 localhost 指手机自身，访问电脑的局域网 HTTP 地址通常仍无法获得麦克风权限。手机联调需可访问、证书受信任的 HTTPS 地址，并转发 HTTP 与 WebSocket 到后端。不要通过 file:// 打开页面。

本文给出可执行步骤和验收标准，不声明已在所有设备或真实上游通过。示例文字是协议说明；真实测试是否成功，以本次浏览器的实际文字和 done 事件为准。

本服务使用固定的服务间 API Key。服务端 .env 配置 SERVICE_API_KEY，业务后端在 WebSocket 握手、能力接口和指标接口传入 X-API-Key: <固定Key>。每个请求只允许一个该头，值精确匹配；缺少、错误或重复返回 HTTP 401。WebSocket 在升级前拒绝，不占用转写名额或创建上游。Key 不从 URL、cookie 或 start 消息读取；未配置则拒绝启动。

浏览器原生 WebSocket 不能设置自定义头，应通过业务后端或可信网关连接，由其验证用户权限并在 HTTP 能力读取和 WebSocket Upgrade 转发中注入 Key。页面和录音模块不携带服务 Key；/demo 没有匿名例外。/demo、/guide、静态资源和 /docs 仍可直接打开，/docs 可通过 Authorize 联调；/healthz 和 /readyz 免鉴权。

服务 Key 与模型供应商 Key 分开配置，只保存在后端，不写入前端源码、URL、浏览器存储或日志。线上使用 HTTPS/WSS。本服务不检查浏览器 Origin，用户登录和业务权限仍由产品负责。

  • providers[].id 是 start 可选的供应商标识；model 是服务端当前配置的模型名，不能用 start.model 覆盖。
  • configured 只表示凭据已配置。接口不调用模型，不证明上游连通、余额、权限或识别效果。
  • languages 是当前模型完整的 {code, name} 语言清单，使用本服务的统一代码；auto_detect 表示自动识别是否已确认。
  • 未知或自定义模型返回 language_support_known: false、languages: []、auto_detect: null，不能据此宣称支持全部语言。
  • default_provider 推荐已配置项：优先 Qwen，其次 FunASR，均无配置时为 null。正常服务启动要求至少配置一个。
  • audio 是固定格式；两个时长值是配置上限，本次会话以 ready 为准。
页面推荐值与协议默认值要分清

省略 start.provider 时，协议仍默认 qwen。即使能力接口推荐 FunASR，前端也必须显式发送 "provider":"funasr"，否则可能得到 provider_unavailable。

前后端不同端口时，由可信服务器代理将 /v1/asr（含 WebSocket Upgrade）和 /v1/asr/capabilities 转发到后端，并从服务器环境注入 Key；不能把它打包到前端配置。录音模块复制到前端静态目录。当前后端未配置跨源 HTTP CORS；跨源 WebSocket 可连接，不代表跨源 fetch 或模块导入也可用。HTTPS 页面应连接 WSS。

多语言与自动识别

页面和录音模块默认不指定语言提示。start.language 省略、null 或 "auto" 均为自动识别；已知录音语言时可传 ja、ko、fr、ar 等代码。服务识别原语言文字，不做翻译、不返回检测语言，也不能把所选提示冒充检测结果。

当前 fun-asr-realtime 支持 30 种语言，qwen3-asr-flash-realtime 提供 27 个语言代码。两者范围不同，菜单应读取对应供应商的完整列表。Qwen 包含粤语 yue、土耳其语 tr、乌克兰语 uk、冰岛语 is；FunASR 包含荷兰语 nl、希腊语 el 等，但没有独立 yue 提示。准确模型版本也会影响范围，fun-asr-realtime-2026-02-28 仅列出 zh/en/ja。

代码忽略大小写和首尾空白，兼容常用别名，如 en-US → en、ja-JP → ja、pt-BR → pt；并非所有地区标签都自动截取前缀。菲律宾语统一传 fil，也兼容 tl，后端自动适配 FunASR 的 tl 与 Qwen 的 fil。中文地区别名不表示繁简输出转换。语言参数是提示，不能当作强制锁定。

已知模型不支持显式所选语言时，在调用上游前返回 invalid_language。未知模型仍可直接传入语法合法的代码，由上游决定；页面只显示“不指定语言（模型能力未确认）”，不宣称已确认的语言范围。

切换供应商时保留仍受支持的选择；若不再受支持，保留原选择并提示重选，直到明确选择自动识别或受支持语言后才能录音。录音中不能切换语言。阿拉伯语等结果可通过输入框的 dir="auto" 自动选择书写方向。

启动兜底只在语言兼容时生效：显式提示须被备用模型支持；自动模式要求备用模型覆盖主模型的全部已知语言。因此当前两个默认模型之间不会在自动模式下跨供应商兜底。未知模型不能作为备用目标，invalid_language 不重试、不触发兜底；已经转发音频后仍不会切换。

2026-11-04 已通过当前 MaaS 网关跑通日、韩、法、德、西、俄、阿、越、泰、印尼、印地语的短合成音频，以及日语/法语自动识别和一次英语后接日语的录音，均有中间结果和 done。这些验证确认通路，不代表完整识别质量评估或任意混说保证。清单依据：FunASR 客户端参数、Qwen 实时客户端参数。

接入录音模块

复用相邻的三个 ES 模块：recorder.js、pcm-worklet.js、pcm-resampler.js。复制时保留相对目录关系。默认 Worklet URL 相对于 recorder.js 自身解析；修改 workletUrl 后，也要保证 Worklet 能找到重采样模块。

构造参数 timeouts 可覆盖各阶段毫秒值，例如 timeouts: { ready: 40000, done: 40000 }。默认 init: 30000、ready: 20000、flush: 3000、done: 25000，只覆盖指定项；值必须为 1 到 2147483647 的有限数字，未知字段拒绝。init 覆盖权限、模块加载及 WebSocket 打开前的初始化；ready 从 WebSocket 打开并发送 start 开始；flush 从停止采集请求开始；done 从尾包发完并发送 stop 开始。

后端增大 OPEN_TIMEOUT_SECONDS 时同步增大客户端 ready，增大 FINISH_TIMEOUT_SECONDS 时同步增大客户端 done，并为队列排空和网络传输留余量。示例 40 秒适用于后端 30 秒预算并留 10 秒余量，并非默认承诺。客户端不会从 capabilities/ready 自动读取这些预算，后端仍独立执行自己的限制。

上面的调用是 API 说明，不应在页面中连续执行。start() 在进入 recording 后 resolve；录音期间调用 stop() 会在收到 done 后 resolve 为原始 done 对象，失败时 reject。也可通过 done 事件处理成功。每次录音新建实例，组件卸载时调用 cancel() 并解绑监听器。

connecting 时调用 stop 按取消处理；尚无会话时 stop 不做任何事。cancel 会令待决的 start/stop 以 cancelled 拒绝并发出 cancelled 状态，通常不发 error 事件。活动会话中重复 start 以 invalid_state 拒绝，也不保证触发 error 事件。方法调用仍需 try/catch，并通过状态禁用重复开始。

事件event.detail页面处理
statechange{state}更新按钮与状态。
transcript原始后端 transcript 对象用 full_text 替换语音区域。
done原始后端 done 对象应用最终全文、解锁编辑。

模块继承 EventTarget。属性 state 取值为 idle / connecting / recording / stopping / done / error / cancelled。同步在状态回调中取消或重启时，状态通知按发生顺序串行发出。

输入框完整示例

这段示例用于与后端同源的页面。本次语音追加在原文之后，每次更新仅替换语音部分。录音期间输入框只读；取消恢复原文，失败保留已确认文字，卸载忽略旧会话的迟到事件。产品的“发送”按钮也应在活动状态中禁用。

React/Vue 受控输入应把 textarea.value 改为 state/ref 更新，同时保留“原文 + 本次快照”和会话身份校验。如果需要在光标处插入，录音开始时保存原文、原始选区及左右文字，固定边界后替换语音区域。空结果、取消或没有确认文字的失败要恢复完整原文和原始选区，不能删掉原先选中的文字；连续录音保留上次语音结束处的光标。旧会话事件不能改写新一轮内容。录音中允许编辑时，需要另做范围追踪和冲突处理。

完整 WebSocket 协议

端点为 ws://localhost:8000/v1/asr，线上使用对应的 WSS 地址。业务后端在握手请求头添加 X-API-Key，浏览器通过注入该头的业务代理连接；握手鉴权失败为 HTTP 401，不会进入后续协议。控制消息是 JSON 文本帧，音频是二进制消息。start、stop 与 audio 配置不接受未定义字段。每次录音使用一条新连接。

start → ready → PCM / transcript → flush → stop → transcript → done

PCM 上传与转写接收并行。无有效语音时可能没有 transcript，done.full_text 可以为空。

1. 客户端发送 start

WebSocket open 后立即发送，默认等待上限为 5 秒。

已知模型支持哪些语言以能力接口为准。语言提示不支持时返回 invalid_language，语法不合法时返回 invalid_start。其他 provider、音频格式、未知字段会被拒绝；录音中不能重复 start 或切换供应商。

2. 服务端返回 ready

上游准备成功后才发送。推荐等 ready 后再开始采集和上传，本仓库录音模块遵循该顺序。当前后端也会缓存 ready 前收到的 PCM（默认最多 3 秒）及提前收到的 stop，待上游就绪后按顺序转发；超出缓存上限报 pre_ready_overflow。建连中放弃应直接取消并关闭连接。

  • type 固定为 ready；session_id 为会话字符串标识；provider 为本次实际供应商；audio 为固定音频格式。
  • 若服务端启用了备用供应商且语言范围兼容，建连时切换会额外返回 fallback_from，值为原请求供应商。自动模式要求备用模型覆盖主模型全部语言。默认未启用；ready 后不会在录音中切换供应商。
  • max_session_seconds 是 ready 后到 stop 的实际经过时间上限，单位秒。
  • max_audio_seconds 是累计上传音频的时长上限，单位秒。
  • max_audio_chunk_bytes 是单条音频二进制消息字节数上限。

限制均为数字，以本次响应为准。前端应在时限前主动停止，给尾包传输留出余量。

3. 客户端发送二进制 PCM

使用 ws.send(arrayBuffer) 或 ws.send(typedArray)。内容为无容器头的 16 kHz、16-bit signed little-endian、单声道 PCM。每包非空、偶数字节，且不超过 ready 声明的分片上限。

用 full_text 替换本次语音区域，不能 +=。confirmed_text 同样替换，较早段落迟到时可能重新排序。服务端按模型原文直接拼接，不自动添加段间空格、标点或换行。

5. 客户端发送 stop

唯一字段 type 必须是 stop。重复 stop 幂等，stop 后继续发送音频会报 audio_after_stop。发出后继续接收转写，不能立即关闭连接。

6. 服务端返回 done

type 固定为 done，session_id 标识会话，full_text 是最终全文并允许为空。audio_seconds 为已成功转发的 PCM 字节数除以 32000，单位秒，不是实际经过时间或计费承诺。

只有 done 表示完整成功。服务收到上游结束事件并确认没有未定稿文字后发 done，随后以 1000 关闭连接。单独收到 close，即使 close code 为 1000，也应视为未完整结束。stop 后默认最多等待 15 秒，超时返回错误。

7. 服务端返回 error

type、code、message、confirmed_text 均为字符串。type 固定为 error，code 用于程序分支，message 是诊断文字，confirmed_text 为可保留的已确认快照。session_id 通常是会话字符串；并发已满或服务重启导致会话未创建时为 null。前端按 code 映射中文提示，不依赖 message 的具体拼写。失败后连接关闭，不继续等待成功。

握手鉴权失败返回 HTTP 401，响应为 {"detail":"Invalid or missing API key"}，业务后端应检查请求头。浏览器通常只观察到握手失败，需要通过代理排查。握手失败、网络断开和权限失败可能没有服务端 WebSocket JSON 错误。自行实现客户端时，应保存最近的 confirmed_text，未收到 done 就断开时提示中断、舍弃临时文字。录音模块通过 error 事件统一提供 code、message 和 confirmed_text。

音频与停止顺序

浏览器设备常见采样率是 44.1/48 kHz。使用 AudioWorklet 读取 Float32 音频，按实际 AudioContext.sampleRate 处理，混为单声道，连续低通滤波重采样到 16 kHz，再转换为 PCM16LE。直接抽点会混叠，每包独立重采样可能在边界断裂；只声明 16 kHz 不会改变真实采样。

MediaRecorder 通常输出 WebM/Opus 等编码容器，不能直接上传。改后缀或 MIME 类型也不会转换成 PCM。复用本仓库模块时无需另写 MediaRecorder 流程。

  1. 用户操作触发权限与 AudioContext.resume；ready 前不上传，真正开始采集后才显示“正在录音”。
  2. 限制本地队列并监控 WebSocket.bufferedAmount。拥塞时明确中断，不无限缓存或静默丢包。
  3. 点击停止后进入 stopping，阻止新采集，令 Worklet flush 内部尾包并等待确认。
  4. 尾包通过同一 WebSocket 按序发完，再发送 stop，不能让控制消息越过音频。
  5. 保持接收，继续处理 transcript，直到 done 或 error。界面显示“正在等待最后一句定稿”。
  6. 完成、失败、取消、卸载均释放 MediaStreamTrack、AudioContext、Worklet、计时器和监听器。取消后迟到的权限授权和事件也需清理。

取消直接关闭会话，协议没有 {"type":"cancel"}。取消不保证撤销已发送音频的处理或用量；产品应恢复原文，不能把临时文字当最终结果。

done编辑、重新录音使用最终全文，释放资源。
error编辑、重新录音保留原文与 confirmed_text，舍弃临时文字。
cancelled编辑、重新录音恢复原文，忽略旧连接的后续事件。

正常路径为 idle → connecting → recording → stopping → done，活动状态可进入 error 或 cancelled。connecting 阶段的“停止”可映射为取消，不能发送 stop。终态后用新实例、新 WebSocket 开始。

出现标点、某段 is_final、一段时间没出字，都不是整次录音完成的依据。临时结果可能纠错和重新排序。录音时锁定编辑能避免快照覆盖用户手动输入。

错误与恢复

错误时保留已确认文字并释放资源；根据错误原因提示用户重试或排查。不要自动重连重放本次音频，新连接没有续传位置，重放可能重复出字和产生额外上游用量。

浏览器失败与连接拒绝

模块还可能产生本地错误。microphone_denied 提示开启麦克风权限；microphone_not_found / microphone_unavailable 提示检查设备与系统权限；microphone_ended / audio_suspended 表示采集中断；insecure_context / unsupported_browser 提示使用 localhost 或 HTTPS 及支持 AudioWorklet 的浏览器。

network_backpressure / audio_overflow 表示网络或页面处理跟不上音频速度；connection_error / connection_closed 表示连接失败或提前断开；initialization_timeout / ready_timeout / flush_timeout / done_timeout 表示对应阶段超时。audio_error / protocol_error / initialization_error 及未知 code 均需通用提示，不能让界面永久忙碌。cancelled / invalid_state 也可能作为方法 Promise 的拒绝原因，由调用方 catch。

并发已满返回 server_busy，服务停止接入时返回 shutting_down；两者的 session_id 为 null，随后以 1013 关闭连接。反向代理、网络故障或旧部署可能直接拒绝握手；传输层超大消息也可能直接关闭。任何未收到 done 的异常关闭都要处理。

联调验收

以下为待执行的验收标准。模拟供应商测试验证协议，真实浏览器、设备采样率、手机权限与真实上游效果仍需按实际环境验证。

场景操作与通过条件
能力读取获取 capabilities；选择已配置项，start 明确包含所选 provider。
正常中文说两句，中间停顿后停止；有文字更新、done、完整尾句，麦克风指示消失。
多语言用自动识别及受支持的语言提示测试；原语言有快照、有 done，不把提示当检测结果。
供应商切换切到不支持原语言的供应商；保留选择并提示重选，明确选择后才能录音。
快照纠错连续说长句；多次更新只替换语音区域，没有重复整句。
原文保护先输入文字再录音；原文保留、录音期间锁定、完成后可编辑。
停止尾包最后一个词后立即停止；stopping 可见，尾包在 stop 前，最终词出现在 done。
取消建连、录音、结束等待中分别取消；恢复原文、释放资源、旧事件不改写页面。
权限拒绝重置并拒绝权限；提示明确，可重试，输入框恢复，没有永久忙碌状态。
无设备 / 设备占用移除或禁止可用设备；提示设备问题，释放会话，不显示成功。
中途断网阻断网络或停止后端；没有 done 就显示中断，只保留 confirmed_text，不重放。
空录音保持静音后停止；能结束、允许空全文，实际空文本与否由模型决定。
接近时限按 ready 限制提前停止；不等超限后再声明成功。
重复录音 / 卸载连续两次录音，录音中离页；新会话不串旧快照，离页释放设备与连接。
44.1 / 48 kHz 设备分别测试可用设备；发送 16 kHz PCM，语速音高正常，无边界杂音。
手机浏览器用受信任 HTTPS 地址；权限可授予、WSS 可达，停止和取消与桌面一致。
